# 2026-09-28: Web Chat — FastAPI + Nuxt over the local Qwen3.8-Flash-Next agent

**Status:** implemented on branch `feature/web-chat` from `PRPs/netbox-web-chat.md`
(brief: `PRPs/initials/netbox-web-chat.md`). Run book: `docs/setup/web-chat.md`.

## What was built

- `src/web/` — FastAPI backend (`python -m src.web`, `127.0.0.1:8010`): one long-lived
  `NetBoxDeepAgent`, `WS /ws/chat` with a `{type, content, completed, metadata}` chunk protocol,
  `/health`, `/status`, `/models`, `/conversations/{id}/messages`, `/conversations/{id}/usage`.
- `frontend/` — Nuxt 3 chat UI (`:3010`) ported from `claude-agentic-sdk/frontend`, with tool
  activity, cancel, context gauge, token ledger and compaction dividers.
- `scripts/ws_smoke.py` — reference client for the protocol (used for Gate 3 below).
- Agent additions only: `NetBoxDeepAgent.stream_events()` and `get_history()`.
  `query()`, `NETBOX_SYSTEM_PROMPT`, middleware and skills are byte-identical to master.

## Decisions

1. **Lock, not `--parallel`.** `scripts/serve_qwen4exp.sh` runs one slot and the MCP client is a
   stdio subprocess. `TurnRunner` serialises turns with one `asyncio.Lock`, reports queue position,
   and cancels via `Task.cancel()` on the task consuming `agent.astream()`, which closes the HTTP
   stream and frees the slot. Adding `--parallel` would split the KV budget per slot on a model
   where that is unmeasured.
2. **`stream_mode=["messages", "updates"]`** for the web path only. "messages" gives token
   deltas and the trailing usage chunk; "updates" gives `AIMessage.tool_calls` from the `model`
   node and `ToolMessage`s from the `tools` node. Middleware hook nodes (dotted names) are
   ignored except `SummarizationMiddleware.*`, which is a secondary compaction signal.
   *Measured (Gate 3): streaming tool-call parsing under `--jinja` works on this model — three
   calls in one turn, all with well-formed dict args and `status=ok` results. The `["updates"]`-only
   fallback the PRP reserved was not needed.*
3. **Conversation id == LangGraph `thread_id`.** The agent already had `InMemorySaver` + a
   per-call `thread_id` override; the server generates ids (`uuid4().hex`) on `new_conversation`.
   Memory is per process; the UI shows a "server memory lost" banner after a backend restart.
4. **Token numbers are the server's.** `create_llamacpp_model()` now sets `stream_usage=True`
   (langchain-openai 1.2.1 auto-enables it only for the default OpenAI URL, so it was silently
   off) and constructs `LlamaCppChatOpenAI`, a 12-line subclass that copies llama.cpp's `timings`
   block into `response_metadata`. The per-call `usage` chunk therefore carries resident context
   (`input_tokens`), `cache_read`, and real `prompt_per_second` / `predicted_per_second`.
   Nothing in the UI uses `count_tokens_approximately` (the ~19x undercount noted in
   `tests/eval/run_session.py:40-50`).
5. **Compaction detection** = `input_tokens` of call N+1 < 0.8 x call N; one
   `context_compacted` chunk per turn. The trigger (0.85 x `n_ctx` = 111,411 on the live server)
   is exposed by `/status` so gauge and backend agree.
6. **The silent empty reply is now visible.** `finish_reason == "length"` with zero visible text
   becomes an `error` chunk (kind `length`) carrying the turn's usage, instead of nothing.
7. **Ports once each:** `WEB_PORT` (8010) in `src/web/config.py`; `3010` in
   `frontend/nuxt.config.ts`. 8000 is NetBox, 8001/8002 the claude app, 58123 llama-server.
8. **Blocking start-up probe gated.** `LLAMACPP_VALIDATE_ON_INIT` (default `true` keeps the CLI
   unchanged); `src/web/__main__.py` sets it to `false` for its own process.

## First user-found defect: the 120 s streaming watchdog (fixed same day)

User query in the browser: *"How many power outlets does each Halvorsen Logistics PDU
provide, and how many PDUs are there?"* (thread `f67a764b`). After 6 model calls and 7 tool
calls (4m 06s, 58,566 tokens read, 56,398 cached) the turn died with
`StreamChunkTimeoutError: No streaming chunk received for 120.0s ... chunks_received=0`.

LangSmith per-call timeline: model calls 1-6 took 11-25 s each on 8.7k-10.9k of context; the
7th tool result (`netbox_get_objects` on the tenant's devices) was **64,199 chars**; the 7th
model call received **0 chunks in 120.2 s** and was killed by langchain-openai's
`stream_chunk_timeout` (default 120 s, async streaming only, measures the gap between parsed
chunks). llama-server emits nothing during prefill, and prefilling ~18k new tokens on this box
takes longer than 120 s. The CLI/eval path is non-streaming and was never exposed to it; the
web path is the first streaming consumer.

Fix: `create_llamacpp_model()` passes `stream_chunk_timeout=None` unless
`LLAMACPP_STREAM_CHUNK_TIMEOUT_S` is set (documented in `.env.example`). The web layer's own
cancel path covers genuine hangs.

Verified by re-running the same query on a fresh thread after the restart: 7 model calls,
6 tool calls, 324 s, correct answer (12 APC AP7901 PDUs, 8 outlets each, 96 total). The 7th
call prefilled **19,976 new tokens** (context 30,673, cached 10,697) at 119.6 t/s, i.e.
~167 s of silence before the first chunk - exactly the window the 120 s watchdog was killing.
Turn ledger: read 89,080 / cached 67,130 / written 1,258; context end 30,673 (23.4%).

## Second user-found defect: "Queued behind 1 other turn" on an idle server (fixed)

The `queued` chunk carried the sender's own slot number in the wait list (1 = first), and the
UI rendered that as "behind N other turns". Now `position` = turns actually ahead (the running
turn, if any, plus earlier waiters); 0 when the turn starts immediately, and the UI shows the
queue notice only when it is > 0.

## Added 2026-09-29: per-turn LangSmith trace links

Each turn now mints its LangGraph root `run_id` in `TurnRunner` and passes it via
`stream_events(..., run_id=)` -> `config["run_id"]`. `src/web/tracing.py` resolves the LangSmith
tenant + project ids once at startup (`Client().read_project(LANGCHAIN_PROJECT)`) and builds
`.../o/<tenant>/projects/p/<project>/r/<run_id>?trace_id=<run_id>`. `run_id` and `trace_url` ride
on `done`/`error`/`cancelled` metadata and on `TurnUsage` in the ledger; the footer shows
"trace ↗" (new tab). Verified: the minted id resolves via the API to the recorded run, and the
browser link opens smith.langchain.com in a new tab. Turns that predate minted ids are
backfilled: `GET /conversations/{id}/traces` lists the thread's root runs from LangSmith
(`filter=and(eq(metadata_key,"thread_id"), eq(metadata_value,<id>))`, limit capped at 100 by the
API) and the UI matches each linkless assistant turn to the run whose `end_time` is nearest its
finish timestamp (within 5 min). Verified on the 7-turn thread `cc16da50`: 7/7 matched in order.
Also fixed while here: `useChatSocket()`
registered `onMounted`/`onUnmounted` when called from plain functions (Vue warnings); hooks are
now registered only inside a component instance. Same-day UI additions: RTF research logo
(`BrandLogo.vue`, `public/logo.svg`) and level headers via `--app-header-h`.
